# ADR 0001：选用 LangGraph 状态图作为 Agent 编排方案

- 状态：**已接受**
- 日期：2026-08-30
- 决策者：项目 owner

## 背景

需要把 v1 的"单趟 RAG 管线"升级为能调用工具、能拆解多步任务的 Agent。编排方案三选一：

| 方案 | 可控性 | 生态 | 工程深度体现 |
|---|---|---|---|
| 自研状态机 | 最高 | 无 | 最高 |
| **LangGraph** | 高 | 成熟 | 中 |
| Dify（低代码） | 低 | 成熟 | 低 |

## 决策

**采用 LangGraph 的 `StateGraph`**，保留自研护栏与治理层。

## 理由

1. **降低编排的重复劳动**：条件边、状态归约、检查点、interrupt 都是成熟能力，自研要重写一遍且容易出 bug。
2. **生态与招聘市场对齐**：LangGraph 是当前 Agent 编排的事实标准之一，简历关键词匹配度高。
3. **不牺牲可控性**：状态图是显式跳转，条件边是我们自己的纯函数，不是 LLM 自由发挥 —— 保留了自研方案的核心优势。

## 重要影响：LangGraph 不替你做治理

这是本次决策**最需要明确的认知**。LangGraph 只解决"编排"，治理仍需自建：

| 能力 | LangGraph 提供 | 本项目自建 |
|---|---|---|
| 编排 | StateGraph、条件边、检查点、interrupt | — |
| 护栏 | 仅 `recursion_limit` | 步数 / token / 墙钟预算、死循环检测 |
| 工具治理 | 无 | 工具级授权、幂等键、审批门、审计 |
| 观测 | 需接 LangSmith | OTel span 树、成本归因（M3） |
| 评测 | 无 | 黄金集、对抗集、CI 门禁（M3） |

**结论：编排成本下降，治理成本不变。** M1 的核心工作量在右侧自建部分。

## 备选方案为何未选

- **自研状态机**：价值最高但重复劳动多，且偏离行业主流技术栈。
- **Dify**：搭建快，但工程深度体现不足，工具治理定制空间受限，不适合作为技术作品集。
